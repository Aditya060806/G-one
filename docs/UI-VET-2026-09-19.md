# App UI review — 19 September 2026

## Findings fixed

- Live Monitor's breadcrumb was an overlay over the scrollable content. It now occupies its own layout space above the scrolling panel.
- The wearable firmware emits STEMP (skin temperature), not TEMP (core temperature). The primary temperature card now graphs skin readings. Core temperature remains a separate card only when the source provides it or simulation is enabled. Skin readings are never substituted into core-temperature anomaly detection.
- Motion and temperature cards use full width, and compact-card labels can wrap without pushing values and status badges off screen.
- Empty charts display an explicit no-readings state; no synthetic trace is added.
- Shared telemetry plots retain timestamps, discard non-finite values, and expand their range to include spikes above nominal bounds. Single readings remain visible as points.
- Light-mode temperature lines and values use darker amber for contrast.
- Partial sensor packets no longer cause a card to lose its last available reading while that reading remains in its chart window.
- Chart accessibility summaries retain attached units such as °C and %, and ignore invalid values.

## Verification scope

Unit regression coverage includes large motion spikes, irregular timestamps, invalid/duplicate points, single skin readings, and attached unit suffixes. Existing parser tests cover STEMP separately from TEMP. The full unit suite covers monitoring, anomalies, SOS policy, sessions, and other app logic.

Two instrumented layout tests have been added for scrolling in light mode and larger text in dark mode. They have not been run: the emulator and release optimizer exhausted available machine memory during the first build attempt. Physical BLE readings and SMS delivery were not exercised. No emergency message was sent.

This review addresses the reported defects and related chart/layout issues; it is not a claim that every device-specific app behavior is defect-free.
